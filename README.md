# Minesweeper — клиент-серверная игра

Сетевая версия «Сапёра» с рейтингом, статистикой, мультиплеером и админ-панелью.

## Возможности

- **Одиночная игра** — три сложности, классический и timed-режимы
- **Сетевые аккаунты** — регистрация, логин, bcrypt-хэши паролей, смена пароля
- **Личный рейтинг** — лучшее время на сложность × режим, отдельно для классики и timed
- **Личная статистика** — сводка по режимам, история партий, график времени побед
- **Друзья** — заявки, принятие, поиск, live-бейдж через push-уведомления
- **Мультиплеер** — комнаты до 4 игроков на общем поле, real-time синхронизация
- **Рейтинг мультиплеера** — суммарные очки по всем партиям
- **Статистика мультиплеера** — сколько партий, побед, среднее число клеток
- **Приглашение друзей в комнату** — через push в реальном времени
- **Админка** — управление пользователями, записями, рейтингами, аудит действий
- **Безопасность** — TLS/HTTPS, bcrypt, CSRF, rate limiting

- Java 17+
- Maven 3.8+

## Подготовка БД

```sql
CREATE DATABASE minesweeper CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'minesweeper'@'localhost' IDENTIFIED BY 'minesweeper_pass';
CREATE USER 'minesweeper_admin'@'localhost' IDENTIFIED BY 'admin_pass';
GRANT SELECT, INSERT, UPDATE, DELETE ON minesweeper.* TO 'minesweeper'@'localhost';
GRANT SELECT, INSERT, UPDATE, DELETE ON minesweeper.* TO 'minesweeper_admin'@'localhost';
FLUSH PRIVILEGES;
```

Затем выполни `db/schema.sql`. Он создаст все таблицы:

| Таблица | Назначение |
|---------|-----------|
| `users` | Аккаунты игроков и админов |
| `game_records` | Одиночные партии (сложность, режим, время, победа) |
| `leaderboard` | Личные рекорды (сложность × режим) |
| `friendships` | Дружба и заявки, одна строка на пару игроков |
| `mp_records` | Партии мультиплеера (клетки, взрыв, победа, очки) |
| `mp_leaderboard` | Суммарный рейтинг мультиплеера (очки, партии, победы) |
| `admin_actions` | Аудит действий администратора |

## Сборка

```bash
mvn clean package
```

Все четыре модуля собираются в fat-JAR'ы. Готовые артефакты:

- `common/target/minesweeper-common-1.0-SNAPSHOT.jar`
- `server/target/minesweeper-server-1.0-SNAPSHOT.jar`
- `client/target/minesweeper-client-1.0-SNAPSHOT.jar`
- `admin/target/minesweeper-admin-1.0-SNAPSHOT.jar`

## Запуск

### 1. Игровой сервер

Без TLS (для разработки):

```bash
java -jar server/target/minesweeper-server-1.0-SNAPSHOT.jar
```

С TLS:

```bash
java -Dtls.cert=server-cert.pem -Dtls.key=server-key.pem \
     -jar server/target/minesweeper-server-1.0-SNAPSHOT.jar
```

С параметрами (опционально):

```bash
java -Drooms.threads=8 \
     -Dtls.cert=server-cert.pem -Dtls.key=server-key.pem \
     -jar server/target/minesweeper-server-1.0-SNAPSHOT.jar
```

Конфиг БД читается из `db.properties` в текущей директории (см. `db.properties.example`). Значения можно перекрыть переменными окружения `MINESWEEPER_DB_URL`, `MINESWEEPER_DB_USER`, `MINESWEEPER_DB_PASS`.

Системные свойства сервера:

| Свойство | По умолчанию | Назначение |
|----------|--------------|------------|
| `tls.cert` / `tls.key` | — | Пути к PEM-файлам для TLS (без них — plain TCP) |
| `rooms.threads` | `2 × ядер`, мин. 4 | Размер пула потоков для игровых комнат |
| `debug.allowMines` | `false` | **Только для тестов.** Разрешает запрос карты мин в комнате |

### 2. Клиент

```bash
java -jar client/target/minesweeper-client-1.0-SNAPSHOT.jar
```

В диалоге логина:
- Имя и пароль — при первом входе нажми «Регистрация»
- Сервер / порт — по умолчанию `localhost:9000`
- Галочка TLS — включи, если сервер с TLS
- Сертификат — путь к `server-cert.pem`

Меню клиента:

- **Игра** — режим (Классика / На время), выбор сложности
- **Аккаунт** — моя статистика, статистика мультиплеера, друзья, смена пароля
- **Сеть** — лобби, рейтинг классики, рейтинг мультиплеера

### 3. Админка

```bash
java -jar admin/target/minesweeper-admin-1.0-SNAPSHOT.jar
```

Расположена на **https://localhost:8443**. Логин по умолчанию — `admin` / `admin123` (хэш хранится в `application.properties` как bcrypt-хэш).

Разделы админки:

| Путь | Что показывает |
|------|----------------|
| `/` | Обзор: пользователи, партии, победы, топ-5 по сложности × режиму |
| `/users` | Пользователи, смена роли, удаление, история партий |
| `/records` | Одиночные партии, фильтр по режиму |
| `/leaderboard` | Рекорды по сложности и режиму |
| `/mp` | Рейтинг мультиплеера |
| `/mp/records` | Партии мультиплеера |
| `/audit` | Аудит действий администратора |

## Как играть с другом

Клиент поставляется с упакованной Java (`jpackage --runtime-image`), поэтому другу **не нужны** ни JDK, ни Maven, ни MySQL. Ему нужен только установщик клиента и ваш сетевой адрес.

### Сценарий 1: вы в одной сети (Wi-Fi, точка доступа)

Самый простой случай. Проброс портов и внешний IP не нужны.

**Хост (вы):**

1. Узнайте свой локальный IP:
   ```powershell
   ipconfig
   ```
   Смотрите `IPv4-адрес` активного адаптера (Wi-Fi или Ethernet). Обычно это `192.168.x.x` или `172.20.10.x` на iPhone-хотспоте, `192.168.43.x` на Android.

2. Разрешите входящие подключения на порт 9000:
   **Пуск → Параметры → Сеть и Интернет → Брандмауэр Защитника Windows → Дополнительные параметры → Правила для входящих подключений → Создать правило → Для порта → TCP → 9000 → Разрешить → все профили → Имя: `Minesweeper Server`.**

3. Если Wi-Fi имеет профиль «Общественная сеть» — смените на «Частная» в **Параметры → Сеть и Интернет → Wi-Fi → Свойства сети**.

4. Запустите сервер (без TLS — в одной сети шифрование не критично):
   ```bash
   java -jar server/target/minesweeper-server-1.0-SNAPSHOT.jar
   ```

5. Запустите свой клиент и введите в диалоге логина **свой локальный IP** вместо `localhost`. Если логин прошёл — сервер доступен по сети.

**Друг:**

1. Установите `Minesweeper-1.0.0.exe` и запустите.
2. В диалоге логина:
    - **Имя:** любое
    - **Пароль:** любой (мин. 4 символа)
    - **Сервер:** ваш локальный IP (например, `192.168.0.42`)
    - **Порт:** `9000`
    - **TLS:** снять галочку
3. Нажмите **Регистрация**, затем **Войти**.

### Сценарий 2: вы в разных сетях (интернет)

Понадобится проброс порта на роутере и внешний IP.

**Хост (вы):**

1. Узнайте внешний IP — например, на https://2ip.ru.
2. Узнайте локальный IP:
   ```powershell
   ipconfig
   ```
3. Зайдите в админку роутера (`http://192.168.0.1` или `http://192.168.1.1`) и настройте **Port Forwarding** (может называться «Виртуальные серверы», «NAT»):

   | Поле | Значение |
      |------|----------|
   | Внешний порт | `9000` |
   | Внутренний порт | `9000` |
   | Внутренний IP | ваш локальный IP |
   | Протокол | `TCP` |

4. Разрешите порт 9000 в брандмауэре Windows (см. Сценарий 1).
5. Запустите сервер.
6. Проверьте проброс на https://2ip.ru/check-port/ — порт 9000 должен быть открыт.
7. Передайте другу **внешний IP и порт**.

**Друг:** те же шаги, что в Сценарии 1, только в поле «Сервер» вводит ваш **внешний IP**.

> **Важно:** проброс не работает, если у вас «серый» IP (провайдер использует NAT). Проверить просто: сравните внешний IP на 2ip.ru с IP в админке роутера (раздел WAN/Status). Если они разные — у вас серый IP. Варианты: попросить у провайдера «белый» IP, использовать туннель (playit.gg, ngrok) или арендовать VPS.

### Сценарий 3: мобильная точка доступа

То же, что Сценарий 1, но есть нюансы:

- **Раздаёте вы** — друг подключается к вашей точке, вводит ваш IP (узнаётся через `ipconfig` на вашем ноуте, обычно `172.20.10.x` на iPhone или `192.168.43.x` на Android).
- **Раздаёт друг** — роли меняются: он запускает сервер, вы подключаетесь к его точке.
- **Раздаёт третье устройство** — оба подключаетесь к нему, у каждого свой IP в его сети.

### Проверка связи до игры

Прежде чем звать друга, проверьте, что хост виден в сети. С ноутбука друга:

```powershell
ping 192.168.0.42
```

(замените на ваш локальный IP). Должны идти ответы. Если ping не проходит:

- Оба подключены к **одной** SSID (не один к «5G», другой к «2.4G», если роутер раздаёт их как разные сети).
- В настройках роутера выключена **«AP Isolation»** / **«Client Isolation»** / **«Изоляция клиентов»** — часто включена на гостевых Wi-Fi.

### Про TLS в локальной сети

TLS-сертификат привязан к имени хоста. Если сертификат сгенерирован с `CN=localhost` и `SAN=dns:localhost,ip:127.0.0.1`, то при подключении по `192.168.0.42` рукопожатие упадёт с `no name matching 192.168.0.42 found`.

Для игры в одной сети **проще отключить TLS**:

- Хост запускает сервер без `-Dtls.cert` / `-Dtls.key`.
- Друг снимает галочку TLS в диалоге логина.

Трафик внутри Wi-Fi никто снаружи не видит, шифрование избыточно.

Если TLS всё же нужен — перегенерируйте сертификат с вашим локальным IP:

```bash
openssl req -new -x509 -key server-key.pem -out server-cert.pem -days 3650 ^
    -subj "/CN=192.168.0.42" ^
    -addext "subjectAltName=IP:192.168.0.42"
```

И передайте другу обновлённый `server-cert.pem` (он должен лежать рядом с `.exe`).

### Приглашение друга в комнату

После того как оба зашли в игру:

1. Добавьте друг друга в друзья: **Аккаунт → Друзья → Поиск игроков**, найти имя, нажать «Добавить». Второй принимает заявку.
2. Кто-то один создаёт комнату: **Сеть → Лобби → Создать комнату**.
3. Внутри комнаты владелец нажимает **«Пригласить друга»** и выбирает второго игрока.
4. У второго мгновенно всплывает диалог приглашения — нажимает «Присоединиться».
5. Владелец нажимает **«Начать игру»** — оба видят одно поле.

## Режимы игры

### Классика

Таймер считает вверх. Победа — все не-минные клетки открыты. Проигрыш — открыта мина.

### На время (Timed)

Таймер обратного отсчёта. Лимит зависит от сложности:

| Сложность | Поле | Мин | Лимит |
|-----------|------|-----|-------|
| Новичок | 9×9 | 10 | 60 сек |
| Любитель | 16×16 | 40 | 180 сек |
| Профессионал | 16×30 | 99 | 420 сек |

Победа — все не-минные открыты до истечения таймера. Проигрыш — мина или время вышло.

Рейтинги классики и timed хранятся раздельно — у одного игрока могут быть два рекорда на одной сложности.

## Мультиплеер

Комнаты до 4 игроков на общем поле. Сервер — единственный источник правды: клиент отправляет `DIG`/`FLAG`, получает `ROOM_UPDATE_PUSH` и рендерит поле.

### Правила

- Каждый видит одно и то же поле.
- Клик по клетке открывает её **всем**. Flood fill тоже распространяется на всех.
- Наступил на мину — выбыл из партии, но игра продолжается для остальных.
- Победа — все не-минные клетки открыты. Побеждают все живые.
- Проигрыш — все игроки взорвались.
- Флаги можно ставить на закрытые клетки. Снять чужой флаг может любой, но счётчик уменьшится тому, кто его поставил.

### Очки

За каждую партию мультиплеера каждый игрок получает счёт:

```
score = revealedCells
      + (win ? totalSafeCells / 2 : 0)
      - (exploded ? 1 : 0)
```

- `revealedCells` — сколько клеток открыл лично игрок (включая flood fill после его клика)
- `totalSafeCells` — количество не-минных клеток на поле
- Победа даёт бонус в половину поля
- Каждый взрыв — минус одно очко

Очки суммируются в `mp_leaderboard` по всем партиям — это рейтинг мультиплеера.

### Приглашение друзей

Владелец комнаты в состоянии `WAITING` может пригласить друга через кнопку «Пригласить друга». Получателю мгновенно приходит `FRIEND_INVITE_PUSH` — клиент показывает диалог с подтверждением.

## Протокол

Собственный бинарный протокол поверх TCP:

```
+---------+--------+------------------+
| length  |  type  |     payload      |
| 4 байта | 1 байт |  length байт     |
+---------+--------+------------------+
```

- `length` — длина payload в байтах (защита от мусорных кадров: не больше 1 МБ)
- `type` — ordinal `MessageType`
- `payload` — JSON (Jackson)

Порядок в pipeline: `TLS → Decoder → Encoder → RateLimiter → Handler`.

Типы сообщений делятся на группы:

- **Авторизация:** `REGISTER_*`, `LOGIN_*`, `CHANGE_PASSWORD_*`
- **Одиночная игра:** `SUBMIT_SCORE_*`, `LEADERBOARD_*`, `MY_STATS_*`
- **Друзья:** `FIND_USER_*`, `ADD/ACCEPT/DECLINE/REMOVE_FRIEND_*`, `GET_FRIENDS_*`, `COUNT_FRIEND_REQUESTS_*`, `FRIEND_*_PUSH`
- **Мультиплеер:** `CREATE/JOIN/LEAVE/LIST/START_ROOM_*`, `DIG_REQUEST`, `FLAG_REQUEST`, `ROOM_UPDATE_PUSH`, `ROOM_FINISHED_PUSH`
- **Рейтинг мультиплеера:** `MP_LEADERBOARD_*`, `MP_STATS_*`
- **Служебные:** `PING`, `PONG`, `ERROR`, `DEBUG_GET_MINES_*`

Полный список — в `common/.../protocol/MessageType.java`.

## Безопасность

- **Пароли игроков** — bcrypt (`spring-security-crypto`)
- **Пароль админа** — bcrypt, хранится хэшем в конфиге
- **Транспорт клиента** — TLS (опционально)
- **Админка** — HTTPS + CSRF-защита
- **Аудит** — все действия админа логируются в `admin_actions`
- **Rate limiting** — token bucket на каждый канал, отдельные лимиты для логина, поиска игроков, DIG/FLAG
- **Идентификация** — `userId` берётся из сессии канала, а не из запроса
- **Debug-режим** — `DEBUG_GET_MINES` доступен только владельцу комнаты и только при флаге `-Ddebug.allowMines=true`, при старте печатается предупреждение

## Известные ограничения

- **Одна сессия на аккаунт.** При входе с другого устройства старое соединение вытесняется.
- **Комната закрывается при выходе владельца.** Переизбрание владельца не реализовано.
- **Нет реванша.** После финиша комнату нельзя перезапустить — надо выйти и создать новую.
- **Debug-хук для тестов.** `DEBUG_GET_MINES` включён только флагом и работает только для владельца комнаты.
